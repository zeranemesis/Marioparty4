# Attente réseau et invitations courtes — 4 septembre 2026

L'arrêt définitif pour absence de progression passe de 10 à 120 secondes. La première connexion native dispose aussi de 120 secondes. Après cinq secondes sans progression, le jeu affiche une attente ; il reprend lorsque les entrées manquantes arrivent avant l'expiration. Les divergences de configuration et de contexte restent bloquantes. La simulation ne passe jamais silencieusement hors ligne. Une connexion TCP déjà fermée n'est pas reconnectée automatiquement.

Correction de retransmission : lorsqu'un joueur répète une ancienne entrée, le joueur en avance renvoie sa propre entrée conservée pour ce même tick. Auparavant, cette demande était rejetée parce que le tick était déjà dépassé localement, ce qui pouvait bloquer définitivement les deux participants après une perte de paquet. Le message de la capture ne prouve pas que ce cas était la cause de cette partie particulière.

Le canal TLS attend désormais jusqu'à 120 secondes pendant la session (la négociation initiale reste bornée à huit secondes). Cela tolère une interruption temporaire ; une fermeture explicite, une erreur réseau définitive ou une incompatibilité peuvent encore arrêter immédiatement le salon.

Invitation PB2 : exactement 60 caractères au lieu de 159. Elle contient l'adresse IPv4, le port, l'expiration à la seconde, les 128 premiers bits de l'empreinte SHA-256 du certificat et un secret aléatoire de 128 bits. Le secret est haché pour le message d'authentification. La comparaison SHA-256 complète des exécutables/DLL est effectuée lors de la connexion TLS ; elle n'occupe plus de place dans le code. La comparaison intégrale du disque reste inchangée. Les anciens codes ne sont pas acceptés ; utiliser cette version sur les deux PC et créer une nouvelle invitation. Aucun serveur d'annuaire externe n'est ajouté.

Validation : compilation native et compagnon réussie. 80 contrôles du compagnon, y compris code de 60 caractères, expiration, mauvais certificat/secret/version, autorité de l'hôte et disques différents. Deux vrais exécutables en mode sonde ont terminé 1 200 ticks via TLS malgré une pause de 12 secondes sur le client et la suppression d'une entrée jusqu'à ce que son émetteur ait dépassé le tick concerné. Les tests natifs de progression couvrent une reprise après 60 secondes et l'arrêt terminal à 120 secondes par horloge simulée. Les tests natifs transport, runtime et rollback passent. Les tests ne modifient ni la box ni le pare-feu. Une partie graphique complète entre deux réseaux reste à valider.
